# engine/ : MIE stage 1, native C++ engine (week 0 skeleton)

Branch `cpp/stage1`, cut from the Python reference at ff313e2. The Python files of this
repository are the reference and are not changed by this branch.

## What does not exist

No scoring, no rules engine, no executable parser, no archive reader, no signature check, no
worker process, no quarantine, no folder watching, no window, no installer. `mie-service`
answers `status` with `"engine":"absent"`. Nothing here scans a file or gives a verdict.

## Building and testing

Only in GitHub Actions: `.github/workflows/engine.yml` (Windows and Ubuntu runners). It is
not built on developer machines. Third-party versions follow from one pinned vcpkg commit;
`third_party/pins.json` lists the libraries and `tools/vuln_check.py` checks them against the
OSV database on every push.

No EICAR file and no malware is used by any test here. All test inputs are generated bytes.

## Rules that bind this code

The design and the reviewer's conditions: `DESIGN_STAGE1.md` (kept with the coordination
records, not in this repository) and r-01's rulings B-3484 and B-3488. In short: every parser
of untrusted bytes will run in a separate low-rights worker; the parity profile reproduces the
Python reference exactly and never ships; no scoring code before the synthetic parity set's
manifest exists; no claim without a CI record.
